# Wiki tooling

> Boundary: the scripts that keep the wiki honest and findable. NOT covered: the page format they
> enforce ([schema](../SCHEMA.md)), the code gates ([gates](gates.md)).

## Purpose

Prompts 2 and 3 need a command to find the pages that cover a file, and a check that the wiki is
consistent. Without them «read before acting» depends on the agent's goodwill.

## Rules

1. `npm run wiki:lint` runs, in order: front-matter check against [the schema](../SCHEMA.md) (types,
   statuses, required fields, `approved_on` only with `approved`), broken relative links, every
   `depends_on` and `canonical` path exists (canonical may be empty only while `planned`), index
   freshness (`wiki:index --check`), `check-acceptance`, and `agents-lint` (AGENTS.md ≤ 32 KiB).
2. `npm run wiki:index` regenerates [`index.md`](../index.md): the `spec` pages as one numbered list
   in build order (topological order of `depends_on`, ties broken by path in alphabetical order),
   each line with link, title and status; then the `concept` pages, then the `record` pages, each by
   path. `--check` exits 1 if the file on disk differs. Round zero wrote the file by hand in exactly
   this format.
3. `npm run wiki:context -- <files…>` prints the pages whose `canonical:` contains any of the files
   (or a parent folder of them), with title and status.
4. `npm run wiki:touched` crosses `git diff --name-only HEAD` (plus staged and untracked files) with
   every `canonical:`; prints the pages to re-check and the changed files that no page covers.
5. `check-acceptance` hashes (SHA-256) the text of each page's `## Acceptance criteria` section and
   compares it with `wiki/acceptance.lock.json`. A missing or different hash fails, naming the page.
   `npm run acceptance:lock -- <page>` writes the current hash; AGENTS.md reserves it to humans.
   The first lock is created from the pages exactly as committed in round zero.
6. Scripts are Node ES modules in `scripts/wiki/`, with a shared parser for front matter and
   sections (one module, used by all of them). Every script has `--selftest`.

## Acceptance criteria

1. [auto] `npm run wiki:lint` passes on the repository as committed in round zero plus this page's
   work.
2. [auto] Each script's `--selftest` builds a broken case in a temporary directory (missing front
   matter field, broken link, stale index, edited acceptance section) and exits 0 only if the script
   rejects it.
3. [auto] `npm run wiki:context -- game/src/domain/run.ts` lists `game/run.md` once that page is
   built (until then, a fixture in the selftest proves the mapping).
4. [auto] `index.md` regenerated by `wiki:index` lists pages in an order where every page comes
   after all of its `depends_on`.
5. [auto] Changing one character of an acceptance section makes `wiki:lint` fail with the page name.

## References

- Topological sorting with Kahn's algorithm: repeatedly take a node with no unprocessed
  predecessor; choosing the smallest available node gives a deterministic order
  (https://en.wikipedia.org/wiki/Topological_sorting#Kahn's_algorithm).
- SHA-256 through Node's `crypto.createHash('sha256')` (https://nodejs.org/api/crypto.html).
- Node's built-in test runner (`node --test`) runs the script tests without a dependency
  (https://nodejs.org/api/test.html).

## Canonical files

- `parse.mjs` is the one parser (front matter subset, sections, hashing); `coverage.mjs` decides
  whether a `canonical:` entry (a file or a folder) covers a file; `fixture.mjs` writes the small
  valid wiki every selftest breaks.
- `lint.mjs` runs, in order: front matter, links (outside code spans), `depends_on`/`canonical`
  paths, `index.mjs --check`, `check-acceptance.mjs`, `agents-lint.mjs`. If the first three find
  anything it stops there, because the index cannot be rendered from broken front matter.
- `npm run wiki:selftest` runs every script's `--selftest`; `npm run check` runs `wiki:lint` and
  `wiki:selftest`.
- `wiki:touched` reports files under `wiki/` neither as covered nor as uncovered: they are the
  documentation itself.
